**Model:** MobileNetV3-Small, 5 classes (healthy, leaf rust, leaf miner, Cercospora, Phoma). Held-out test set, n = 2,066:

| Measure | Result |
|---|---|
| Accuracy | 0.74 |
| Macro-F1 | 0.67 |
| Leaf rust precision / recall | **0.79 / 0.93** |
| Healthy precision / recall | **0.79 / 0.94** (4 of 139 healthy test leaves called rust) |
| Accuracy by source | JMuBEN 0.72, BRACOL 0.77, RoCoLe 0.83 |
| Calibration error | 0.063 after temperature scaling |
| Model size | **1.65 MB** (int8) |

## 2. What our data does **not** cover (scored)

| Gap | Why it matters | What we did about it |
|---|---|---|
| **East African healthy leaves.** JMuBEN, the only Kenyan source, has no usable healthy images: its ~19k "healthy" images are near-copies of one or two leaves. Healthy is learned from Brazil (BRACOL) and Ecuador (RoCoLe, Robusta). | False-positive behaviour on Noor's own healthy leaves is untested. | JMuBEN healthy is used for training only. Healthy is evaluated on other leaves. Field data collection is the first pilot task. |
| **Test set from the same collections as training.** | Real accuracy on new farms and phones will be lower. | The simulation blends the measured error rates 30% toward a pessimistic matrix (`ClassifierConfig.field_shift`), with sensitivity tests on top. |
| **Background conditions.** BRACOL is shot on white paper; JMuBEN is tight crops. | A phone photo of a leaf on the tree looks different. | Background augmentation in training. RoCoLe field photos are included. The app asks for one leaf filling the frame. |
| **Early rust is often missed.** 23 of 31 rust-called-healthy errors are the earliest severity. | Early warning is where the model is weakest. | The phone shows **"Not sure — ask a person"** for weak or ambiguous results. Villages are scanned for *many* weak signals, and nearby farmers are asked to check. |
| **Weak classes**: Phoma recall 0.24, Cercospora precision 0.46. Most rust false positives come from other diseases. | Look-alikes can trigger false rust signals. | The scan conditions on each farm's own baseline, and alerts need several farms plus confirmations. |
| **Leaves only.** No berries, coffee berry disease, coffee berry borer or red spider mite. | The model forces any photo into one of its 5 classes. | The UI asks for a leaf. The fail-safe catches low-confidence results. Stated in the About text. |
| **Small evaluation counts** for healthy, Cercospora and per-source classes (20–140 test images each). | The estimates are noisy. | Counts are smoothed before simulation. Numbers are reported with this caveat. |
| **Impact numbers are simulated.** There's no field trial or real farmer behaviour. | Lead time and loss avoided are model outputs. | Every number is labelled "simulated". Assumptions are in `pestwatch/config.py`, including coffee yield and price. Features that did *not* help are reported. |
| **Translations are drafts.** Swahili and French were written by us. | Wrong advice in a farmer's language is a real risk. | Marked draft and pending native-speaker review. |
| **Less-supported languages** (e.g. Kikuyu, Luhya, Kalenjin). | Most farmers' first language isn't Swahili or English. | Adding a language means a new catalog plus keywords (`scripts/new_language.py`), with no code changes. A language isn't served until marked reviewed. Voice for low-resource languages could start from Meta MMS (brief §7.3). |
